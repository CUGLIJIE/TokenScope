# TokenScope 项目设计

首次云端同步识别缺少客户端、尚未登录和普通网络故障。前两种状态分别显示安装指引或登录窗口。用户选择登录后，由对应配置目录下的 Codex App Server 启动浏览器授权并处理回调。平台核对完成通知、重新读取身份，再触发该配置的同步。登录链接仅在当前操作期间使用，Windows 凭据由 Codex 的系统凭据库存储。取消、超时和服务退出会释放登录会话。

目标是让 Windows 用户用现有 ChatGPT 登录查看 Codex 账号用量，并在同一个工作台分析 Codex、Claude Code 的本机明细。浏览器负责展示，本地 Python 服务负责采集、校验和查询，SQLite 保存计数与同步状态。运行时无需 npm、云服务器或联网下载页面资源。

## 采集和信任边界

|入口|最小采集单位|身份和覆盖范围|
|---|---|---|
|Codex app-server，标准输入输出上的请求/响应|账号日汇总、账号历史指标、额度快照|由对应 CODEX_HOME 的已登录客户端访问服务。验证 ChatGPT 身份，绑定用户与工作区的摘要，定期重查。|
|Codex rollout JSONL|有时间戳的 token_count|使用 session_meta 和 turn_context 提供的会话及模型上下文。优先取累计计数增量，跳过相同快照。|
|Claude Code 项目 JSONL|assistant 消息中的 usage|按 message.id 和 requestId 识别重复流式片段，缓存读取及创建分别保留。|
|JSON 数组、带表头 CSV|单条明细|显式事件 ID、账号、工具、模型、带时区时间和 Token 分类。其他工具可直接采用此契约。|

账号配置独立于采集实现。一个本地目录对应一个账号标签，日志有混合身份时需要先按来源拆分。界面允许添加账号、暂停采集、手动刷新。平台不接管登录凭据，SQLite 仅保存身份摘要、路径、别名、数字与时间。

## 数据流与模型

采集器 → 格式检查与标准化 → SQLite 事务 → 按视图与条件查询 → 统计图和导出。云端以账号和服务端日期为主键更新。明细以账号、工具、事件 ID 为键；导入冲突拒绝整批写入。日志按文件记住字节偏移及解析上下文，文件截断后重扫。云端与明细使用独立事实表，两张表之间没有可靠的逐请求关联。

明细 input_tokens 含读取缓存及创建缓存，output_tokens 独立；cached_tokens 表示读取缓存，cache_write_tokens 表示写入。总量等于输入加输出。上游云端只给总量时分类为空。时间存 UTC，明细按采集机器的本地日期聚合。云端保留服务给出的日期，避免人为移动日边界。

## 查询与展示

范围支持近 7、30、90 天、所有已记录日期和自定义闭区间。日均的分母是选中区间的日历天数；峰值为区间内单日最大用量；活跃天数按正用量计。月累计图在每月一号重新累计，选择部分月份时仅累计范围内的记录。热力图按周排列。工具、账号、模型和导出共用查询条件。账号终身累计单独展示，不计入区间总和。

## 部署、故障和验证

Python 3.10+ 标准库，静态 HTML/CSS/JS，HTTP 仅绑定 127.0.0.1。写请求校验同源、自定义请求头和正文上限。默认数据库位于当前用户 LocalAppData。后台线程启动时和每 15 分钟同步，也支持手动触发。后台收集错误不会覆盖已成功入库的数据，额度与用量独立显示可用性。客户端版本不支持的调用保持不可用。
